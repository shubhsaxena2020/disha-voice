# Contributing to Disha Voice

Thanks for your interest in contributing. This project is a prototype, not a release-ready product. Contributions should improve its usefulness while protecting the dignity, privacy, and safety of blind and low-vision people.

## Before you start

- Check the existing documentation and open issues for related work before starting a large change.
- For substantial changes, open an issue or discussion first, if available, to agree on scope. Do not include private media or sensitive personal information in a public issue.
- Keep pull requests focused. Explain the problem, the change, how you tested it, and any known limitations.
- Follow the existing style and conventions in the part of the project you change. Add or update tests and documentation when appropriate.

## Safety and product boundaries

- **No medical claims:** Do not present Disha Voice as diagnosing, treating, preventing, or monitoring a medical condition, or as providing medical advice. Avoid clinical claims about accuracy or outcomes.
- **No navigation or mobility claims:** Do not claim or imply that the app can guide travel, identify a safe path, detect all hazards, prevent collisions, or replace a cane, guide dog, orientation-and-mobility training, or a human assistant. Object descriptions and image-relative positions are not navigation instructions.
- Describe uncertainty and limitations plainly. Do not turn model outputs into confident assertions when the evidence is uncertain. Do not claim detection, language, offline, latency, accessibility, or device support that has not been verified.
- Keep accessibility and the perspectives of blind and low-vision users central. Do not assume automated checks replace testing with assistive technologies or user feedback.

## Privacy and media

- **Never contribute private media**: no private photographs, video, audio, recordings, screenshots, or other media belonging to an identifiable person or captured in a private setting. Do not submit media merely because names or faces have been blurred.
- Do not commit personal data, credentials, API keys, signing keys, tokens, location histories, or private conversation content. Use synthetic or clearly licensed public test fixtures that are appropriate to redistribute.
- Respect the consent, privacy, copyright, and license terms of any data or assets. Document provenance and license for new third-party assets or datasets. Do not upload private media to issue trackers, pull requests, CI, or model services.

## Submitting a change

1. Create a focused branch from the current project branch.
2. Make the smallest complete change and add tests where practical.
3. Run relevant checks and list the exact commands and results in your pull request. If a check could not be run, say so; do not imply it passed.
4. Review the diff for unrelated changes, private data, secrets, unlicensed assets, and unsupported safety or medical claims.
5. Open a pull request using the template. Be prepared to revise or clarify the change during review.

By submitting a contribution, you confirm that you have the right to contribute it under the repository's applicable license, if one is present. A contribution is not accepted until maintainers review and merge it. Do not assume that a license or project governance policy exists if it has not been published.

## Questions

For project usage and contribution questions, see [SUPPORT.md](SUPPORT.md). For vulnerability reports, follow [SECURITY.md](SECURITY.md); do not report vulnerabilities in public issues or pull requests.
